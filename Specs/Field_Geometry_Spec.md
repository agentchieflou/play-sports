# Specification: Field Geometry and Scaling

This document sets out the field's dimensions and its frame in world space. The numbers live in
data, not here: `Data/field_dimensions.json` (`FPSFieldDimensions`) is the one authority, read
through `PSField` (`PSFieldDimensions.h`). Every system places and reads the field through it:
the game mode's line of scrimmage, the field grid's end-zone and out-of-bounds volumes, every
spot read from a world location, and the field you see (`APSFieldSurface`, Epic 146.3).

## Scaling convention

Unreal Engine's unit is the centimetre. The field's scale is `CentimetresPerYard`, so the
convention is documented in the data.

- **The game's yard is a metre (`CentimetresPerYard` = 100).** Every distance tuned in cm elsewhere
  (lineups, routes, coverage depths, kick distances) is read against it, so the field keeps the
  proportions of a regulation field at that scale.
- A regulation yard is 91.44 cm. Setting `CentimetresPerYard` to 91.44 would make the field
  real-world sized. The layout follows it (`PlaySports.Field.MarkingsLayout` checks both scales),
  but every cm-tuned distance would then need retuning.

## Dimensions

| Component | Yards (`field_dimensions.json`) | World cm at 100 cm/yd | At 91.44 cm/yd |
| --- | --- | --- | --- |
| Playing field, goal line to goal line (`FieldLengthYards`) | 100 | 10,000 | 9,144 |
| Each end zone (`EndZoneDepthYards`) | 10 | 1,000 | 914.4 |
| Total, end line to end line | 120 | 12,000 | 10,972.8 |
| Width, sideline to sideline (`FieldWidthYards`) | 53.3333 | 5,333.33 | 4,876.8 |
| Out-of-bounds depth past the boundary (`OutOfBoundsDepthYards`) | 14 | 1,400 | 1,280.2 |

## The frame

The offense's own goal line is X = 0 and it always attacks +X. Yard line N, counted from that
goal line, is at X = N × `CentimetresPerYard`. Y = 0 is the middle of the field, and Z = 0 is the
ground.

- **Near goal line:** X = 0. **Far goal line:** X = `FieldLengthYards` × cm/yd (10,000).
- **Midfield (the 50):** X = 5,000.
- **End lines:** an end zone's depth beyond each goal line (X = −1,000 and X = 11,000).
- **Sidelines:** Y = ± half the width (± 2,666.67).

`PSField` converts both ways: `YardLineToWorld`, `WorldToYardLine`, `WorldToSpot`, `GoalLineX`,
`EndLineX`, `MidfieldX` and `SidelineY`.

## In the level

Nothing needs to be placed or sized by hand:

- `APSFieldGrid` holds the frame's coordinate helpers and spawns the end-zone and out-of-bounds
  trigger volumes on it. The game mode spawns one when the level has none.
- `APSFieldSurface`, which the grid spawns, is the visible field and the ground. It is built at
  runtime from the frame and `Data/field_markings.json` (`Specs/Field_Markings_Spec.md`). The
  ground's top is Z = 0, it reaches the out-of-bounds depth past the boundary, and it has
  collision, so the ball lands on it.
- The default level, `/Game/Maps/GameMap`, is generated by the content pipeline
  (`Specs/Default_Map_Spec.md`).
